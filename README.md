# 💱 Currency Converter API

> API для конвертации сумм между валютами на основе официальных курсов **Национального банка Украины (НБУ)**.
> Курсы обновляются автоматически консольной командой, которую по расписанию запускает cron.

## 🚀 Запуск и проверка

### Требования

- Docker Desktop (Windows / macOS) или Docker Engine + Docker Compose v2 (Linux)
- На Windows — режим **Linux containers** (по умолчанию)
- Свободен порт `8000`

### Быстрый старт

```bash
cp .env.example .env        # затем заполнить значения в .env
docker-compose up -d --build
```

Пример `.env`:

```env
POSTGRES_DB=converter_db
POSTGRES_USER=converter_user
POSTGRES_PASSWORD=converter_password
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
```

> `POSTGRES_HOST` нужен только для локального запуска без Docker — в контейнерах `docker-compose.yaml` подменяет его на `db`.

Порядок старта сервисов:

```
db (healthcheck pg_isready)
 ↓
migrate (alembic upgrade head → завершается)
 ↓
api + cron (cron сразу загружает курсы, затем — раз в сутки в 00:05 по Киеву)
```

### Проверка, что всё поднялось

```bash
docker-compose ps -a
```

Ожидаемо:

| Сервис    | Состояние                 |
|-----------|---------------------------|
| `db`      | `Up (healthy)`            |
| `migrate` | `Exited (0)` — так и должно быть, он отработал и завершился |
| `api`     | `Up`, порт `0.0.0.0:8000->8000/tcp` |
| `cron`    | `Up`                      |

```bash
docker-compose logs migrate
```

```
INFO  [alembic.runtime.migration] Running upgrade  -> 6b8d81fc36b2, create currencies table
```

При повторном запуске строки `Running upgrade` не будет — миграция уже применена.

```bash
docker-compose logs cron
```

```
INFO httpx: HTTP Request: GET https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json "HTTP/1.1 200 OK"
INFO app.cli: Обновлено курсов: 40
```

Если НБУ в момент старта недоступен — в логе будет `ERROR app.cli: Не удалось обновить курсы` и строка `Первичная загрузка курсов не удалась, cron повторит по расписанию`; контейнер при этом продолжает работать.

### Запросы к API

Swagger UI: http://localhost:8000/docs

> Курсы меняются каждый день, поэтому числа в ответах будут отличаться от примеров.

**Успешная конвертация** — `200 OK`:

```bash
curl "http://localhost:8000/api/convert?from_currency=USD&to_currency=EUR&amount=100"
```

```json
{"from_currency":"USD","to_currency":"EUR","amount":100.0,"result":89.22,"rate":0.892189,"rate_date":"2026-10-12"}
```

**Код в нижнем регистре** — приводится к верхнему, `200 OK`:

```bash
curl "http://localhost:8000/api/convert?from_currency=usd&to_currency=eur&amount=100"
```

**Маленький результат** — 6 значащих цифр вместо `0.00`, `200 OK`:

```bash
curl "http://localhost:8000/api/convert?from_currency=VND&to_currency=GBP&amount=100"
```

```json
{"from_currency":"VND","to_currency":"GBP","amount":100.0,"result":0.00292204,"rate":0.0000292204,"rate_date":"2026-10-12"}
```

**Гривна** — курс UAH = 1, у `UAH → UAH` нет даты курса, `200 OK`:

```bash
curl "http://localhost:8000/api/convert?from_currency=UAH&to_currency=UAH&amount=5"
```

```json
{"from_currency":"UAH","to_currency":"UAH","amount":5.0,"result":5.0,"rate":1.0,"rate_date":null}
```

**Неизвестная валюта или металл** — `404 Not Found`:

```bash
curl -i "http://localhost:8000/api/convert?from_currency=XAU&to_currency=USD&amount=1"
```

```json
{"detail":"Валюта XAU не найдена"}
```

**Ошибки валидации** — `422 Unprocessable Entity`:

| Запрос | Причина в `detail[].msg` |
|--------|--------------------------|
| `?from_currency=US&to_currency=EUR&amount=1` | `String should match pattern '^[A-Za-z]{3}$'` |
| `?from_currency=USD&to_currency=EUR&amount=0` | `Input should be greater than 0` |
| `?from_currency=USD&to_currency=EUR&amount=abc` | `Input should be a valid decimal` |
| `?from_currency=USD&to_currency=EUR` | `Field required` |

> Swagger UI проверяет формат параметров сам и при ошибке не отправляет запрос — поэтому коды `422` удобнее смотреть через `curl -i`.

### Обновление курсов вручную

Ровно та команда, которую выполняет cron (с тем же окружением):

```bash
docker-compose exec cron bash -c '. /etc/cron.env; cd /code && python -m app.cli update-rates'
```

| Результат | Вывод | Код выхода |
|-----------|-------|:----------:|
| Курсы обновлены | `INFO app.cli: Обновлено курсов: 40` | `0` |
| НБУ или БД недоступны | `ERROR app.cli: Не удалось обновить курсы` + трейсбек | `1` |
| Не указана команда | `error: the following arguments are required: command` | `2` |

Проверить расписание cron:

```bash
docker-compose exec cron crontab -l
```

```
SHELL=/bin/bash
5 0 * * * . /etc/cron.env; cd /code && python -m app.cli update-rates >> /proc/1/fd/1 2>&1
```

Посмотреть данные в БД:

```bash
docker-compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT code, rate, rate_date FROM currencies ORDER BY code LIMIT 5;"'
```

### Остановка

```bash
docker-compose down       # остановить, данные БД сохраняются в volume
docker-compose down -v    # остановить и удалить данные БД
```

### Локальный запуск без Docker

Нужен Python 3.12 и запущенный PostgreSQL на `localhost:5432`.

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env                 # POSTGRES_HOST=localhost
sudo -u postgres createuser -P converter_user
sudo -u postgres createdb -O converter_user converter_db

alembic upgrade head                 # создать таблицу
python -m app.cli update-rates       # загрузить курсы → "Обновлено курсов: 40"
uvicorn app.main:app --reload        # API на http://127.0.0.1:8000
```

## 📋 Задание

Необходимо реализовать API, которое позволяет конвертировать суммы между различными валютами на основе официальных курсов Национального банка Украины. Курсы должны обновляться автоматически через запуск консольной команды по расписанию.

### Стек

| Область        | Технология                    |
|----------------|-------------------------------|
| Язык           | Python                        |
| Веб-фреймворк  | FastAPI                       |
| База данных    | PostgreSQL                    |
| ORM            | SQLAlchemy (или другая ORM)   |
| Инфраструктура | Docker, Docker Compose        |

### 1. Бизнес-требования (что сделать)

#### 🕒 Парсинг через cron

- Реализовать отдельную **CLI-команду** (скрипт), которая делает GET-запрос к открытому API НБУ (JSON).
- Полученные курсы валют относительно гривны (**UAH**) нужно сохранять или обновлять в базе данных.
- Эта команда должна вызываться через стандартный **cron раз в сутки** (в рамках Docker-окружения).

#### 🔁 Эндпоинт конвертации

- Реализовать GET-эндпоинт **`/api/convert`**.
- **Параметры:**

  | Параметр        | Пример | Описание             |
  |-----------------|--------|----------------------|
  | `from_currency` | `USD`  | Исходная валюта      |
  | `to_currency`   | `EUR`  | Целевая валюта       |
  | `amount`        | `100`  | Сумма                |

- **Логика:** эндпоинт должен возвращать конвертированную сумму. Конвертация должна корректно рассчитываться через **кросс-курс относительно базовой валюты (UAH)**, данные о которой лежат в БД.
- **Формат ответа:** JSON с указанием результата и использованного курса.

### 2. Инженерные требования и архитектура (Quality Gates)

#### 🐳 Docker & Docker Compose

Приложение должно полностью разворачиваться командой:

```bash
docker-compose up -d
```

В конфигурации должны быть:

- сервис **API**;
- база данных **PostgreSQL**;
- контейнер/сервис с настроенным **cron** для запуска скрипта парсинга.

#### 🧩 Single Responsibility Principle (SRP)

Логика должна быть чётко разделена. **Парсинг НБУ**, **взаимодействие с БД** и **расчёт кросс-курса** — это разные ответственности.

#### 🗄️ Паттерн Repository

Вся работа с базой данных должна быть вынесена в отдельный слой (например, класс `CurrencyRepository`).

## 🛠 Проектирование

### 1. Какой ответ пришлёт НБУ на GET-запрос

```python
{'r030': 978, 'txt': 'Євро',    'rate': 50.1385,   'cc': 'EUR', 'exchangedate': '09.10.2026', 'special': None}
{'r030': 981, 'txt': 'Ларі',    'rate': 17.2474,   'cc': 'GEL', 'exchangedate': '09.10.2026', 'special': None}
{'r030': 985, 'txt': 'Злотий',  'rate': 11.4567,   'cc': 'PLN', 'exchangedate': '09.10.2026', 'special': None}
{'r030': 959, 'txt': 'Золото',  'rate': 185061.47, 'cc': 'XAU', 'exchangedate': '09.10.2026', 'special': None}
{'r030': 961, 'txt': 'Срібло',  'rate': 2638.58,   'cc': 'XAG', 'exchangedate': '09.10.2026', 'special': None}
{'r030': 962, 'txt': 'Платина', 'rate': 73966.11,  'cc': 'XPT', 'exchangedate': '09.10.2026', 'special': None}
{'r030': 964, 'txt': 'Паладій', 'rate': 50712.19,  'cc': 'XPD', 'exchangedate': '09.10.2026', 'special': None}
```

> ℹ️ Поле `txt` приходит от НБУ на украинском языке — это данные API, они хранятся как есть.

> ℹ️ Кроме валют НБУ отдаёт металлы (`XAU`, `XAG`, `XPT`, `XPD`) и `XDR` (СПЗ — расчётная единица МВФ). Это **не валюты**, мы их отбрасываем (см. раздел 3–5).

### 2. Как мы оформляем для себя этот ответ

```json
{"code": "EUR", "name": "Євро", "rate": 50.1385, "date": "2026-10-09"}
```

| Поле НБУ       | Наше поле | Преобразование                        |
|----------------|-----------|---------------------------------------|
| `cc`           | `code`    | без изменений                         |
| `txt`          | `name`    | без изменений                         |
| `rate`         | `rate`    | без изменений                         |
| `exchangedate` | `date`    | `DD.MM.YYYY` → `YYYY-MM-DD`           |

### 3–5. Хранение данных

3. Храним **только валюты** — все, что отдаёт НБУ, кроме металлов и СПЗ (сейчас 40 из 45 позиций).

   Исключения задаются явным списком в конфиге:

   ```python
   EXCLUDED_CODES: list[str] = ["XAU", "XAG", "XPT", "XPD", "XDR"]
   ```

   Это **чёрный** список, а не белый: новая валюта у НБУ сама попадёт в БД без правки конфига. Фильтровать по префиксу `X` нельзя — по ISO 4217 на `X` есть и настоящие валюты (`XOF`, `XAF`, `XCD`).

   Фильтрует `CurrencyService.update_rates()` (это бизнес-правило), а не `NBUClient` и не `CurrencyRepository`. Отдельного списка «поддерживаемых» валют нет — поддерживается всё, что есть в БД.

   **UAH** в ответе НБУ нет (это базовая валюта), но конвертация `UAH ↔ X` обязана работать. Поэтому `CurrencyService` считает курс UAH равным `1` и не ищет его в БД (в таблицу UAH не пишем).
4. Получаем данные от НБУ по адресу:

   ```
   https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json
   ```

   и сохраняем в БД все полученные курсы, **кроме `EXCLUDED_CODES`**.
5. В БД **не добавляем** записи о ежедневных курсах, а **обновляем** существующие (одна строка на валюту).

### 6. Таблица `currencies`

```sql
CREATE TABLE currencies (
    id        SERIAL PRIMARY KEY,
    code      VARCHAR(3)     UNIQUE NOT NULL,
    name      VARCHAR(64)    NOT NULL,
    rate      NUMERIC(18, 8) NOT NULL CHECK (rate > 0),
    rate_date DATE           NOT NULL
);
```

> ⚠️ `NUMERIC(18, 8)`: у «дешёвых» валют НБУ отдаёт до 7 знаков после запятой (`VND 0.0017349`, `LBP 0.000501`), а самый дорогой сейчас — 2 цифры до запятой (`GBP 59.1817`); 10 цифр до запятой — запас. С `NUMERIC(15, 4)` VND превратился бы в `0.0017` — ошибка ~2 %.

> ⚠️ `CHECK (rate > 0)`, а не `>= 0`: курс используется как делитель (`to_rate`), нулевой курс дал бы деление на ноль.
> `rate_date NOT NULL`: курс без даты бессмыслен, а дату мы возвращаем клиенту.

Дополнительные индексы не нужны — таблица будет маленькой (`UNIQUE` на `code` и так создаёт индекс).

**Upsert** делается одним запросом, а не «SELECT → потом INSERT или UPDATE» (так нет гонки и лишних запросов):

```sql
INSERT INTO currencies (code, name, rate, rate_date)
VALUES (:code, :name, :rate, :rate_date)
ON CONFLICT (code) DO UPDATE
SET name = EXCLUDED.name, rate = EXCLUDED.rate, rate_date = EXCLUDED.rate_date;
```

Все валюты одного обновления пишутся в **одной транзакции**: либо обновились все, либо ни одна.

### 7. Расчёт кросс-курса

НБУ даёт курсы валют к **UAH**. Если пользователь спрашивает:

> «Хочу узнать, сколько будет 100 USD в EUR»

то делаем следующее. Допустим, в БД сегодня:

| Валюта | Курс к UAH |
|--------|-----------:|
| USD    |    43.5000 |
| EUR    |    50.1385 |

Тогда система выполняет:

```
100 USD
   ↓  × 43.5000
4350 UAH
   ↓  / 50.1385
86.76 EUR
```

**Формула:**

$$
result = amount \times \frac{from\_rate}{to\_rate}
$$

**Кросс-курс:**

$$
cross\_rate = \frac{from\_rate}{to\_rate} = \frac{43.5000}{50.1385} \approx 0.8676
$$

`from_rate` / `to_rate` — сколько гривен стоит **1 единица** валюты (так отдаёт НБУ).

**Точность:**

- все вычисления — только в `Decimal`, никаких `float`;
- `result` считается из **полных** курсов (`amount × from_rate / to_rate`), а не из уже округлённого `cross_rate` — иначе на больших суммах набегает ошибка;
- округление только на выходе, `ROUND_HALF_UP`:
  - `rate` — **6 значащих цифр** (а не 6 знаков после запятой): `1 LBP → GBP ≈ 0.00000846545`, с 6 знаками после запятой это был бы `0.000008` — точность 1 цифра;
  - `result` — если `|result| >= 1`, то 2 знака после запятой (`86.76`); если меньше 1 — 6 значащих цифр: `100 VND → GBP = 0.00293148`, а не `0.00`.
### 8. Формат ответа

После расчёта кросс-курса возвращаем **86.76 EUR**, а также **1 USD = 0.867597 EUR** и дату курсов, по которым считали.

`GET /api/convert?from_currency=USD&to_currency=EUR&amount=100`

```json
{
  "from_currency": "USD",
  "to_currency": "EUR",
  "amount": 100,
  "result": 86.76,
  "rate": 0.867597,
  "rate_date": "2026-10-09"
}
```

> `rate_date` — дата курса НБУ (если у двух валют даты разные — берём более раннюю). Без неё клиент не знает, насколько курс свежий. У UAH даты нет, поэтому для `UAH → UAH` поле равно `null`.
> Pydantic v2 по умолчанию сериализует `Decimal` в JSON как **строку** (`"86.76"`). Чтобы в ответе были числа, как в примере, поля помечаются сериализатором в `float` — уже после округления в `Decimal`.

### 9. Сущности

#### 1️⃣ `Currency`

Главная бизнес-сущность приложения. Представляет **актуальный курс конкретной валюты**.

#### 2️⃣ `NBUClient`

Его ответственность только одна: **получить данные из API НБУ**.

Он **не должен**:

- ❌ работать с PostgreSQL;
- ❌ делать `INSERT`;
- ❌ делать `UPDATE`;
- ❌ рассчитывать кросс-курс;
- ❌ знать о FastAPI.

#### 3️⃣ `CurrencyRepository`

Наш **Repository Pattern**. Ответственность — **работа с валютами в БД**.

Repository должен уметь делать upsert:

- если `USD` существует → `UPDATE`;
- если `USD` нет → `INSERT`.

#### 4️⃣ `CurrencyService`

Здесь находится **бизнес-логика**. У него две основные задачи:

| № | Задача               |
|---|----------------------|
| 1 | Обновление курсов    |
| 2 | Конвертация          |

Сценарий конвертации — Service:

1. получает `USD` из Repository;
2. получает `EUR` из Repository;
3. проверяет существование валют;
4. получает их курсы;
5. рассчитывает cross-rate;
6. возвращает результат.

Ошибки Service бросает **свои** (доменные) исключения, например `CurrencyNotFoundError`, а не `HTTPException` — иначе появится зависимость Service → FastAPI. Перевод в HTTP-коды (404 / 422) делает Router.

#### 5️⃣ FastAPI Router

Router получает `from_currency`, `to_currency`, `amount`, но **сам ничего не рассчитывает** — только передаёт данные в `CurrencyService`.

#### 6️⃣ Схемы API (Pydantic)

Описывают входные параметры и формат ответа эндпоинта. Валидация на этом уровне: коды — 3 латинские буквы (приводим к верхнему регистру), `amount > 0`.

#### 7️⃣ CLI

Её задача — вызвать сервис:

```
CLI
 ↓
CurrencyService.update_rates()
```

А дальше Service сам:

```
NBUClient
 ↓
Repository
 ↓
PostgreSQL
```

#### 8️⃣ Cron

Cron **вообще не должен знать о бизнес-логике**. Он просто запускает команду:

```
cron
 ↓
CLI
 ↓
CurrencyService
 ↓
NBUClient + Repository
```

### 10. Запрет обратных зависимостей

```
Router ──► Service ──► Repository ──► PostgreSQL
  CLI ──►    │
             └──────► NBUClient ──► API НБУ
```

Запрещённые направления:

| Зависимость                | Статус |
|----------------------------|:------:|
| Repository → Service       |   ❌   |
| Repository → FastAPI       |   ❌   |
| NBUClient → Repository     |   ❌   |
| NBUClient → FastAPI        |   ❌   |
| Service → FastAPI          |   ❌   |
| Router → Repository        |   ❌   |
| Router → NBUClient         |   ❌   |
| CLI → Repository           |   ❌   |
| CLI → NBUClient            |   ❌   |

Router и CLI — только «входы» в приложение, они ходят **исключительно через Service**. Конкретные `NBUClient` и `CurrencyRepository` передаются в Service через конструктор (DI), сам Service их не создаёт.

### 12. Граничные случаи и ошибки

| Ситуация                                         | Поведение                              |
|--------------------------------------------------|----------------------------------------|
| Валюты нет в БД                                  | `404`, сообщение какая валюта не найдена |
| Металл или СПЗ (`XAU`, `XDR`, …)                 | `404` — в БД их нет, отдельной проверки не нужно |
| Неверный формат кода (`US`, `123`)               | `422` (валидация Pydantic)             |
| `amount <= 0` или не число                       | `422`                                  |
| `from_currency == to_currency`                   | валюта всё равно ищется в БД (`ABC → ABC` — это `404`, а не `rate = 1`); затем `rate = 1`, `result = amount` |
| `from` или `to` = `UAH`                          | курс UAH = `1`                         |
| БД пустая (курсы ещё ни разу не загружались)     | `404` для любой валюты, кроме `UAH → UAH` |
| НБУ недоступен / вернул мусор при обновлении     | CLI пишет ошибку в лог, завершается с кодом ≠ 0, старые курсы в БД **не трогаются** |
| НБУ перестал публиковать валюту                  | строка остаётся в БД со старым `rate_date`, конвертация работает; по `rate_date` в ответе видно, что курс устарел |

### 13. Cron и первый запуск

- **Первый запуск.** Сразу после `docker-compose up -d` таблица пустая, а cron сработает только в назначенное время — до этого API отвечает 404 на всё. Поэтому cron-контейнер при старте **один раз запускает CLI**, а потом уже запускает `cron` на переднем плане.
- **Таблицы** создаются до первого обращения (миграции Alembic или `create_all` при старте) — и API, и CLI должны работать на пустой БД.
- **Переменные окружения.** Cron запускает задачи с пустым окружением, `DATABASE_URL` из `docker-compose.yml` туда сам не попадёт. Его нужно явно передать (например, выгрузить env в файл при старте контейнера, или прописать в crontab).
- **Время и часовой пояс.** Контейнер работает в `Europe/Kyiv` (`TZ`), задача — раз в сутки вскоре после полуночи по Киеву, когда НБУ уже отдаёт курс на новый день.
- **Логи** cron-задачи перенаправляются в stdout контейнера (`>> /proc/1/fd/1 2>&1`), чтобы их было видно в `docker-compose logs`.
- **Ожидание БД.** `api` и `cron` стартуют после того, как PostgreSQL готова (`depends_on` + `condition: service_healthy` с `healthcheck` на `pg_isready`).
